# Rencana: Hemat Kuota Sectors API (1.000 kredit) — Sync Hanya 20 Perusahaan Potensial

## Masalah saat ini
- Setiap `npm run db:sync` = **35 kredit** (34 ticker × 1 + 1 index), apapun lebar window. Harian = ~1.050/bulan → kuota habis < 1 bulan.
- Window kosong (akhir pekan/libur) **tetap konsum kredit** (response 200). Automation harian tanpa pengaman = pemborosan tersembunyi.
- `--full` +3/ticker, `--flow` +1/ticker, `UNIVERSE=all` ≈ 1.900 — semua tanpa rem.
- Kabar baik: skor potensi bisa dihitung **0 kredit** dari DB lokal (`market_intel_scores`, sinyal, evidence SDG).

## Desain (sesuai pilihan Anda: 20 ticker · seleksi otomatis · badge basi · automation harian)

### 1. Watchlist otomatis "perusahaan potensial" (0 kredit)
- **Tabel baru `watchlist`** (schema.ts + `db:push`): `companyId` (unique), `rank`, `potentialScore`, `scoreBreakdown` (jsonb), `selectedAt`.
- **Modul baru `src/db/watchlist.ts`** — `pickWatchlist(limit)` murni lokal:
  - Skor = 60% `market_intel_scores.total_score` + 15% sinyal terkuat + 15% evidence SDG maks + 10% bonus kondisi DISLOCATION/CONFIRMATION; penalti volume ≈ 0 (suspended).
  - Di-refresh otomatis tiap awal sync; tersimpan dengan rincian skor agar bisa diaudit.
- Perusahaan di luar watchlist **tidak dihapus** — data lama tetap tersaji.

### 2. Sync hemat (`src/db/sync.ts`)
- `syncPrices` hanya iterasi watchlist (default `SECTORS_WATCHLIST_LIMIT=20`).
- **Probe index duluan**: tahap index incremental (1 kredit) dijalankan sebelum harga; jika 0 bar baru → kemungkinan besar libur/akhir pekan → **skip seluruh tahap harga** (hemat 20 kredit/hari non-trading). Cron pun dibatasi hari kerja sebagai lapis kedua.
- Fundamentals: hanya ticker watchlist dengan `report_date` > 30 hari atau kosong (±60 kredit/bulan) — menggantikan `--full` rutin.
- `--flow` jadi `--flow=N` (default 10 teratas, tetap opt-in).
- Skip ticker watchlist yang 3× berturut-turut kosong (kolom `emptyRuns` di watchlist).
- `--dry-run`: cetak seleksi watchlist + estimasi biaya per tahap, **0 panggilan API**.

### 3. Anggaran seumur hidup 1.000
- `SECTORS_TOTAL_CREDIT_BUDGET=1000` + `SECTORS_CREDITS_ALREADY_USED=70` (baseline riil); terpakai = SUM(credits_used) sync_state.
- **Perbaiki akuntansi per-source** (bug dari review: `sectors.index` & `sectors.prices` menyimpan angka kumulatif global → sum jadi dobel-hitung): tulis delta per tahap.
- Sync abort sebelum panggilan pertama bila estimasi run > sisa anggaran; log peringatan saat sisa < 2 pekan burn.

### 4. UI jujur soal kesegaran
- `Footer.tsx`: badge "Live · Sectors API — sisa ±930/1.000 kredit".
- Halaman company + signal detail: badge "data basi X hari" bila `snapshot_date` > 7 hari (untuk ticker di luar watchlist).

### 5. Automation harian (dibuat setelah implementasi)
- CronCreate: **Senin–Jumat 19:00 waktu lokal** ("0 19 * * 1-5", setelah IDX tutup) → jalankan `npm run db:sync` (dengan PATH Node), laporkan ringkasan + sisa kredit. Guard anggaran membuat run aman walau tak diawasi.
